## 博客打开慢 — 诊断与优化
项目：C:\Users\Leneve\Desktop\blog（Express + GitHub API 存储，部署于 Render）

**根因（已测量）**
- `public/index.html` 头部两个渲染阻塞外部资源：
  - Google Fonts (Roboto) — 国内常被墙/慢。
  - cdnjs Font Awesome — 本机实测 >8s 超时，浏览器会等它加载完才首屏渲染，直接导致"打开很慢"。
- 首屏需 3 次串行 API 往返（/api/config → /api/posts → /api/auth/status），每次都从浏览器→Render→GitHub。
- 疑似 Render 免费版冷启动（闲置后首次访问 30–60s）。

**已做的修改**
- server.js：新增 `GET /api/bootstrap`，一次返回 `{config, posts, auth}`（Promise.all 合并，users 只取一次）。
- index.html：移除 Google Fonts，改用系统字体栈；Font Awesome 改 `media="print" onload` 非阻塞加载；`window.onload` 改为只调一次 /api/bootstrap；`switchView('home')` 首屏不再重复拉文章。
- 语法已用 `node --check` + `new Function` 校验通过。

**待办 / 建议（未做，需用户确认）**
- 若要图标在国内 100% 显示，应自托管 Font Awesome（现静态中间件会剥离首路径段，根路径下自托管资源会失效，需先修静态资源前缀逻辑）。
- Render 免费版冷启动：用 UptimeRobot 保活或升级付费套餐。

## 打开文章显示加载圈 — 修复
**根因**
- server.js `GET /api/posts/:id` 读取文章后**同步 await 一次 GitHub 写入**（阅读数+1），每次打开都要等一次 GitHub 写+一次取 sha 的读，串行阻塞响应 → 打开文章慢/转圈。
- 前端 viewPost 在 fetch 完成后才切换视图，打开期间无反馈；首屏全屏 loading 在冷启动时可能无限转圈。

**已修改**
- server.js：阅读数改为 `savePostContent(...).catch(...)` 异步落库，读取接口立即返回，不再阻塞。
- index.html：viewPost 先切到详情视图并显示内联 spinner（不再依赖全屏遮罩），失败显示错误文案。
- index.html：window.onload 增加 8s 超时提示（冷启动友好），loading 不再无限转圈。
- 已用 `node --check` + 实跑启动验证（HTTP 200 正常返回页面，路由注册正常）。
- 注意：文章正文目前被 escapeHtml 转义，Markdown/图片语法不会渲染（设计取舍，非本次范围）。
